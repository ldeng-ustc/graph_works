# BACH E12 原生语义可行性探针

2026-10-02。此目录仅作有界正确性验证，不是正式 E12 adapter，不产生性能结果。
不修改 BACH 上游、既有 E2、共享构建、SG 源码或论文。

## 范围与预期

`native_semantics_probe.cpp` 先直接调用本地 BACH 公共事务 API，分别验证：

- 同 memtable 的重复边、删边和不存在边删除。
- `PersistenceAll` 后，旧边在磁盘、新边/墓碑在内存，以及再次 flush 后的重复和删除。
- `DelVertex` 对入边、出边和属性的可见性；同 ID `PutVertex` 后的行为。
- 原生点查校正，加逐顶点 alive/birth 过滤，是否能满足 E12 的简单有向集合语义。
  覆盖自环、重复/无效操作、dead endpoint、初次加点、删点再加与历史边不可复活。
- 共同 `analytics.h` 的最终边数/存活顶点数、BFS 精确距离摘要、CC 精确最小代表
  摘要，以及 10 次 PR 迭代的质量守恒。PR 质量守恒不等于逐顶点 PR 等价证明。

8 个槽预留，原生阶段全部创建；校正阶段只令 `[0,6)` 存活。使用原生 elastic
策略、正常 1 MiB memtable 阈值、一个后台线程；范围大小设为 8 以缩小正确性样例。
显式强制 flush，避免依靠大输入碰到阈值。运行前预期同 memtable 通过，跨层
`GetEdges` 暴露旧边或重复；原生 `GetEdge` 返回较新的值/墓碑。实际日志见末节。

## 静态依据与适配成本

- `BACH/src/MemoryManager.cpp:191` 的 `GetEdges` 先过滤 tombstone；
  `:322` 的 `merge_answer` 合并两个有序列表，保留相同 dst 的两条记录。
  `BACH/src/Transaction.cpp:108` 再串接磁盘层，已经丢失的新墓碑不能遮蔽旧边。
- `BACH/src/SSTableParser.cpp:129` 同样先去除磁盘 tombstone。
  相比之下 `Transaction.cpp:85` 的 `GetEdge` 先查内存，再按版本文件顺序点查，
  保留 tombstone，可用作小图候选校正。
- `MemoryManager.cpp:93` 的 `DelVertex` 记录删除时间；邻接扫描没有统一检查，
  `PutVertex`（`:43`）也没有清除删除时间。E12 顶点生命周期需要明确的适配状态。
- 本探针的私有校正层仅保存 `alive[capacity]` 1 B/点、`birth[capacity]` 8 B/点，
  用原生 double 属性保存插入 seq（限制小于 2^53，整数可精确表示）。不保留全图
  RAM 边副本。每个源点取候选、按原生有序结果消重，再逐候选调用 `GetEdge`。
  原生 DelVertex 仍执行；重加点的可见性由适配层管理，不能说原生属性已复活。
- `SSTableParser.cpp:103` 的磁盘点查线性读取邻接。若一个持久层的邻接小于
  默认 1 MiB 读取块（出度小于 87381 条 12 B 记录），每个点查会请求整个邻接。
  逐候选校正因而约为 `12 * sum(d(v)^2)` 应用读取字节/完整遍历；复杂度最坏
  为出度平方。实际 cache 和分层分布会改变物理 I/O，此处没有性能实测。
- 以 FR 原始 `E=2,586,147,869, V=68,349,467` 近似最终简单图，`E/V=37.84`。
  在上述单层读取模型中，`sum(d^2) >= E^2/V`，约 1.17 TB 请求字节，而一次
  12 B/边遍历约 31.03 GB；这是模型示意，不能当作最终图或 NVMe 实测下界。
  幂等插入和无效删除的预检查同样引入线性点查，必须计入 mixed_apply。

即使小图校正通过，此方案也不宜直接进入正式 FR 比较。适合的最小上游修复方向是
提供保留墓碑的最新可见邻接归并/扫描；需覆盖 memtable、跨层、compaction 和顶点
生命周期。该工作超出本次 30 分钟可行性判断，探针不擅自修复上游。
